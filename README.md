# CashNarra development build

CashNarra is one Next.js 16 / React / TypeScript application with CSS Modules, Narra v2 tokens and self-hosted Manrope/Inter. Real accounts use Supabase Auth and PostgreSQL; the separately labelled synthetic mode uses fictional Ama Works data. Neither mode makes automatic AI calls.

## Run

Use Node.js 24 and npm. Run `npm ci`, copy `.env.example` to `.env.local`, then `npm run dev -- --port 3100`. Open http://127.0.0.1:3100. Without credentials, use the synthetic demo entry. Manual recording, review, corrections, reports, goals and exports work without AI.

For production compilation run `npm run build`, then `npm start -- --port 3100`. This does not deploy anything. Set `SITE_URL` to the exact origin in use.

## Local Supabase

Docker Desktop must be running. The checked-in configuration uses project `cashnarra-development`, API port 58321 and database port 58322, separate from other local projects.

```powershell
npx supabase start -x studio,imgproxy,storage-api,realtime,edge-runtime,logflare,vector,supavisor,postgres-meta
New-Item -ItemType Directory -Force .local
npx supabase status -o json | Set-Content -Encoding utf8 .local/supabase-status.json
npm run test:supabase
```

The integration script creates synthetic local users and an Ama Works workspace, verifies Auth/RLS/RPC access, and writes local public connection settings only if `.env.local` does not exist. Otherwise copy API_URL and ANON_KEY from local status into the corresponding NEXT_PUBLIC variables yourself. Never expose the service-role key. Restart Next after changing environment settings. Local email is available at http://127.0.0.1:58324. Local confirmation is disabled; hosted configuration must explicitly enable the desired confirmation policy.

Migrations live in `supabase/migrations`; apply in filename order to a new isolated development project. Never reset a production database. `supabase db reset --local` destroys this local project's data; it is only appropriate when deliberately rebuilding disposable development fixtures. The CLI is pinned to 2.108.0 because 2.120.0 misidentified the local database state on this machine.

For Supabase Free, supply the project URL and public anon key, apply migrations in a development project, and configure the site URL plus `/auth/confirm` and `/auth/confirm?recovery=1` redirects. Configure Resend-compatible SMTP in Supabase Auth; the SMTP placeholders are setup guidance, not application-side mail credentials. No provider account or paid resource is created by this repository.

## Verification

- `npm run doctor`: checks Node, required configuration pairs, opt-in AI/voice gates and development call limits without contacting providers or printing keys.
- `npm test`: exact arithmetic, fixtures, posting semantics, goals, drafts and safeguards.
- `npm run lint` and `npm run typecheck`.
- `npm run test:db`: destructive **isolated** database tests, restricted to localhost database named `cashnarra_test`. Default port 55432 and password `synthetic-test-only`; override with TEST_DATABASE_URL only for that disposable database.
- `npm run test:supabase`: actual local Supabase Auth and RLS checks; requires the local status file above.
- `npm run test:e2e`: Edge browser journeys, with the app at port 3100. The real Auth test requires the synthetic credentials generated by test:supabase; otherwise it explicitly skips. Screenshots and exports go to ignored `test-results`.
- `npm run build`: production compilation.

To provision the separate SQL-test database: `docker run --name cashnarra-test-db -e POSTGRES_PASSWORD=synthetic-test-only -e POSTGRES_DB=cashnarra_test -p 127.0.0.1:55432:5432 -d postgres:17`. This is not the Supabase application database.

## AI, voice and privacy

The mock accepts declared sample fixtures only; other text is honestly rejected and can be entered manually. Real extraction, proposed corrections and explanations require AI_ENABLED and a server-only OPENAI_API_KEY. Responses use structured validation, `store:false`, bounded context and no database tools. This setting is not a zero-retention guarantee. Calls are limited to at most 10 per user and 20 per project per day; token output is bounded. Configure provider billing limits separately before opting in.

Voice is disabled until VOICE_ENABLED and VOICE_QUALITY_APPROVED are explicitly set. The optional recorder supports stop/cancel/playback, three-minute capture and 8 MB uploads, editable transcripts and recovery downloads. The initial supported format is single-track WebM/Opus; unsupported browsers retain the text fallback. Server validation counts packet duration and checks timeline bounds before provider calls. Representative transcription quality remains a launch check; do not enable it for real users yet.

Device draft persistence is opt-in and scoped to user/workspace. Shared-device mode avoids persistent financial drafts. The service worker caches public brand assets only. An already-open app can capture offline drafts; a cold offline reload is not promised. Exports are private downloads; protect them on shared devices. Unsaved work must be resolved before logout.

Raw source retention is configurable separately from posted records and correction history. `minimize_my_sources` runs on authenticated reads. Schedule the restricted maintenance minimisation function with a trusted database scheduler for unattended expiry, and define backup retention separately. Account data/deletion requests are queued for operator review; there is no unsafe automatic ledger deletion.
